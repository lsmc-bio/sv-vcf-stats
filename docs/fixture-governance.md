# HG002 fixture governance

The committed fixture corpus is generated by `tools/build_test_data.py` with an
explicit `--source-dir`; there is no source-path default. Generation takes place
in a sibling temporary directory. Only a complete stage that passes record,
index, identity, size, and neutrality checks is published.

Selection uses deterministic behavior set-cover followed by coordinate-order
quantiles. It targets `min(100,max(12,ceil(0.005*source_records)))` and closes
over IDs, mate IDs, partner IDs, events, and duplicate-ID groups. Relationship
closure may increase a fixture to at most 128 records. A larger required group
fails generation instead of truncating a relationship.

Headers are rebuilt with public producer signatures, required contigs, and only
the ALT, FILTER, INFO, and FORMAT declarations used by selected records. The
reference is `GRCh38`, and the single sample is exactly `HG002`. Source paths,
commands, machines, users, run metadata, timestamps, private fields, and
source-derived identifiers are not retained. Neutral ID rewrites update mate,
partner, and event references and preserve deliberate missing or duplicate-ID
behavior.

`test_data/manifest.json` binds every source digest to the inspected
single-HG002 corpus and records source/fixture counts, behavior classes,
sanitization version, output/index digests, and redistribution status. The
plain/compressed query pair comes from one selection. The BCF fixture is derived
from the matching sanitized VCF for semantic parity testing.

## Redistribution decision

The per-fixture status `reviewed-public-derived-data` records this decision:

- HG002 was selected for broad public and commercial redistribution, and
  [NIST Genome in a Bottle](https://www.nist.gov/programs-projects/genome-bottle)
  describes its sequencing data and analyses as publicly available without a
  publication embargo.
- A fixture contains only a deterministic excerpt of variant observations from
  that public subject, rebuilt neutral headers, and factual producer/version
  attribution. It contains no caller source code or binary, command line,
  source path, run metadata, original record identifier, or original complete
  VCF.
- The same review was applied independently to every manifest entry. An entry
  without that exact status causes generation to fail; the builder never
  substitutes a different source.

The software license of a named caller remains its author's license and is not
relicensed by this repository. Fixture redistribution must be reviewed again
before the repository's first public release, particularly if the source
corpus, selection, or retained annotations change. This engineering review is
not legal advice.

Regeneration procedure:

```bash
stage_root=$(mktemp -d)
uv run python tools/build_test_data.py \
  --source-dir /explicit/source/directory \
  --output-dir "$stage_root/test_data"
uv run python tools/verify_test_data.py \
  --test-data-dir "$stage_root/test_data"
uv run python tools/scan_tokens.py \
  --root "$stage_root/test_data" \
  --policy policy/forbidden-token-hashes.json
uv run python tools/scan_tokens.py \
  --root "$stage_root/test_data" \
  --policy policy/neutrality-token-hashes.json --structural
```

Review the staged manifest and independent validator output before replacing the
committed tree. Raw and intermediate VCFs must never be staged in Git.

# Security policy

During private development, report suspected vulnerabilities to a repository
administrator through a previously established private channel. When the
repository becomes public, use its private vulnerability-reporting interface.
Do not open a public issue for an undisclosed vulnerability or include genomic
data, access tokens, or private paths in a report.

Supported versions are listed in published release notes. During pre-1.0
development, only the current default branch is supported.

The runtime accepts local files and standard input. It performs no telemetry.
The only network-capable operation is an explicit, confirmed download of the
pinned public reference profile.
